# Executor 设计

状态：规划，未实施。本页维护执行器内部边界，消息字段以[协议](../contracts/protocol.md)为准，授权和接管以[安全设计](../security/security.md)为准。

## 内部职责

Executor 是被动节点，不运行模型、不保存任务目标、不自主编排工具。执行状态、幂等记录和确认挑战是执行控制数据，不属于智能体任务上下文。

| 单元 | 用途 |
|---|---|
| 会话适配 | 接受已认证的本地或 RustDesk 业务通道，反馈连接状态 |
| 身份与请求校验 | 验证签名、绑定、字段、工具参数及当前权限 |
| 工具注册表 | 保存可用实现及其完整工具声明 |
| 状态与调度 | 串行提交请求状态、确认消费、调度占位及取消决定 |
| 系统能力封装 | 操作系统查询、桌面输入、文件、进程等能力的本地适配 |
| 结果与审计 | 转换本地错误、回传状态、记录执行事实和清理结果 |

执行器不开放直接面向 MCP 或模型的入口。首期限定单交互会话；桌面输入默认串行，其他工具并发上限待实测决定。

## 启停、能力与恢复

启动时识别交互用户、会话状态及权限，在认证与注册完成后按[能力发现](../contracts/protocol.md#能力发现)报告获准公开的数据。不能直接上报未授权用户名、屏幕或进程信息。

工具只接收经过校验的参数。不可中断区段、超时和清理能力由各工具声明。退出时停止接收执行请求，尝试取消在途任务，释放本工具持有的按键、进程句柄和临时资源；不能承诺结束外部共享进程或撤销所有副作用。

重连或进程重启后重新注册能力，对结果未知的副作用请求遵循安全设计的人工核对要求。状态存储、确认消费持久化、崩溃恢复和审计补记的机制及测试尚待技术基线确认。
