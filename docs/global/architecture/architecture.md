# 架构设计

状态：规划，未实施。本文维护组件关系和职责，具体消息只定义在[协议](../contracts/protocol.md)，安全规则只定义在[安全设计](../security/security.md)。

## 目标拓扑

```text
智能体（Codex CLI 或兼容客户端）
       |
       v
MCP 入口适配器（首期）
       |
       v
控制层：身份、策略、确认、工具目录、调度、审计
       |
       v
会话适配器（最小闭环：本地认证通道；后续：RustDesk）
       |
       | 统一业务消息
       v
Windows Executor
       |
       +-- 系统信息、截图、窗口、文件、剪贴板
       +-- 输入、进程、UI 自动化、受限 PowerShell

人工操作者 <--> RustDesk 画面与人工输入通道
                   |
                   v
             会话控制权协调
             同时约束控制层与 Executor
```

RustDesk 位于消息传输及会话协调边界，不位于 Executor 工具执行之后。根据已核实的 RustDesk 源码，直连和中继最终复用会话传输路径，端口转发只搬运字节，不理解 AgentDesk 业务语义；业务消息扩展、排序和背压仍未在 AgentDesk 中验证。后续多入口经同一控制层接入，不新增旁路。

## 职责与数据

| 组件 | 独有职责 | 所持数据 |
|---|---|---|
| 智能体 | 理解用户目标、选择工具调用顺序 | 任务上下文和模型交互 |
| 控制层 | 会话、入口身份、策略、确认界面、调度与统一审计关联 | 请求上下文、权限及确认决定；持久化方式待定 |
| Executor | 被动执行、工具级校验、请求状态及清理 | 执行状态、幂等与确认挑战记录；不保存任务目标 |
| 会话适配器 | 绑定连接、传输业务消息、反馈断连 | 连接与能力版本，不独立决定授权 |
| RustDesk 集成 | 画面、人工输入与控制权协调 | 会话标识及接管状态；复用方式待验证 |

Executor 的内部生命周期见[执行器设计](windows-executor.md)，适配器职责分界见[适配器模型](adapter-model.md)。控制层和 Executor 都需保存本组件的审计事件；最终执行事实以执行器返回的受认证结果为依据。

## 调用与确认链路

1. 入口适配器将调用者凭据映射到可信身份，控制层查询工具声明并执行策略检查。
2. 控制层通过已认证会话传递统一执行请求，执行器完成独立校验和状态登记。
3. 无需确认的请求可调度；需确认的请求由执行器保管挑战，控制层展示并核验审批者。
4. 控制层提交批准或拒绝；执行器验证一次性决定并复核当前权限及会话后执行，或返回拒绝/取消等结果。
5. 执行器回传进度及终态，控制层归一化为入口响应并关联审计。

确认、取消、重发和终态的精确行为见协议，不以“重试执行请求”代替确认提交。接管和恢复由会话协调驱动，具体冻结范围见安全设计。

## 阶段与未知项

技术基线先提供项目骨架；最小认证通道验证单会话只读闭环；MCP 与 RustDesk 顺序接入；人工接管验收后开放写操作。各阶段交付条件见[路线图](../governance/roadmap.md)。

进程部署关系、密钥存储、请求事务、能力缓存、队列持久化和传输背压阈值待确认。首期采取单执行器单会话边界，不承诺跨机器事务或桌面副作用回滚。
