# 扩展性设计

状态：规划。首期只提供 MCP 入口和 Windows 执行能力；多入口、多执行器、控制端工具是后续目标，见[路线图](../governance/roadmap.md)。

## 名称与版本

工具名称采用命名空间，例如候选 `windows.system.info`。注册时同一名称和版本重复必须拒绝，不能静默覆盖；执行器实现类型与设备编号分离。工具契约字段由[工具设计](../contracts/tool-design.md)维护。

消息协议版本、工具契约版本、执行器版本分别管理。不兼容的工具输入或输出变化必须使用新契约版本；消息版本协商及不支持版本的处理见[协议](../contracts/protocol.md)。首期不承诺自动降级或历史客户端兼容。

## 扩展门禁

新增入口实现[适配器模型](adapter-model.md)的转换边界，并证明与原入口的授权、确认、取消和审计结果一致。新增工具提交完整声明和能力验证，不将尚未实现的工具写入发现结果。

多执行器路由、命名冲突处理、能力变化通知和受控重试需在第十一阶段验证。并发控制、隔离和容量上限依赖实际部署测量，当前未验证。
