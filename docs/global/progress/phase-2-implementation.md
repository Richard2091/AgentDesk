# 第二阶段最小运行闭环实施方案

## 目标与范围

状态：进行中。

本阶段交付单控制层、单 Windows Executor、单认证会话和单低风险工具的端到端运行闭环。调用从控制层进入，依次经过完整信封校验、会话绑定、工具查找、参数校验、权限判断、调度、超时或取消、结果校验与归一化，再返回结构化终态。

首个真实工具为 `windows.system.info`，只返回操作系统版本和 Executor 版本，不读取用户名、主机名、进程、屏幕或文件。内部测试工具仅在显式测试配置下注册，用于稳定验证超时、取消和异常，不进入默认能力报告。

非目标包括：生产级 Ed25519 双向认证、密钥轮换和吊销、持久化请求恢复、审计存储、人工确认、MCP、RustDesk、桌面截图、输入、文件或进程操作。这些内容继续由后续阶段负责。

## 项目画像

- 组件：Python 控制层、Python Windows Executor、共享协议模块。
- 运行方式：控制层启动单个 Executor 子进程，通过 UTF-8 单行 JSON 标准输入输出交换业务信封。
- 依赖：`jsonschema` 用于冻结契约的运行时校验；不引入数据库、网络监听或外部服务。
- 数据：会话绑定、工具声明、请求状态、幂等指纹和结构化结果只保存在当前进程内存中。
- 权限：控制层和 Executor 均检查工具声明中的资源与动作；未知权限默认拒绝。
- 暴露面：仅本机子进程标准输入输出；共享密钥来自环境变量，不写入日志或结果。
- 主要风险：跨会话调用、消息篡改、重复执行、取消与完成竞态、超时后后台任务遗留、异常信息泄露。

## 接口与数据模型

所有业务消息使用协议 `0.1` 完整信封。第二阶段本机通道继续使用开发期 HMAC-SHA256 验证信封完整性，并明确标记为开发认证；它不替代第四阶段的 Ed25519 生产认证。信封校验包括版本、字段白名单、RFC 3339 时间、最长有效期、会话/执行器/调用主体绑定、签名和重放随机数。

能力发现返回完整工具声明。执行请求载荷包含工具名、契约版本、参数和可选超时；请求编号位于信封。请求状态保留请求编号、会话、调用主体、业务指纹、状态、结果、错误、执行耗时和取消信号。

控制层与 Executor 均依据同一冻结 Schema 校验工具参数。Executor 对结果再次执行输出 Schema 校验，防止不符合契约的本地结果被报告为成功。

## 状态、并发与一致性

单 Executor 允许有限线程并发，但每个请求的状态变更通过锁串行提交。状态从 `requested` 进入 `executing`，取消时进入 `cancelling`，最终只允许一次进入 `completed`、`failed`、`timeout` 或 `cancelled`。

幂等范围为会话、执行器、调用主体和请求编号。同一请求编号、相同业务指纹只返回已有状态或终态；同一编号但工具、版本、参数或超时不同则返回 `request_conflict`，不得再次调度。

超时和取消通过合作式取消事件通知工具。阶段二注册的真实工具无阻塞副作用，内部测试长任务会定期检查取消事件。Executor 关闭时停止接收新请求、取消活动任务并等待线程释放；无法合作停止的任意第三方工具不在本阶段开放。

## 错误与兼容策略

成功返回 `completed` 及符合输出 Schema 的结果。参数、权限、超时、取消、工具异常和 Executor 异常分别归一化为冻结错误对象，普通响应不包含堆栈、共享密钥或完整敏感参数。

当前 `windows_executor.main` 的旧能力输出仅作为阶段零启动兼容入口；阶段二正式链路使用完整业务信封。旧的简化能力查询在第二阶段验收后不再作为安全闭环证据。

## 实施步骤与完成标准

1. 运行时契约：实现完整信封创建、校验、会话绑定、重放保护和 Schema 校验；完成协议单元测试。
2. Executor：实现工具注册表、系统信息工具、权限与参数双重校验、幂等、调度、超时、取消、异常归一化和关闭清理；完成服务测试。
3. 控制层：实现 Executor 子进程生命周期、能力缓存、预校验、请求发送、状态查询、取消和结果归一化；完成本机集成测试。
4. 验收：覆盖成功、参数错误、权限拒绝、超时、取消、Executor 异常、重放和请求冲突；运行语法、Schema、自动化测试及启动演示；独立复审无必须修复项。

只有代码、自动化测试、可复现演示、文档同步和独立复审全部通过后，才能将第二阶段标记为已完成。

## 发布与回滚

本阶段不发布外部服务，不迁移持久化数据。回滚以阶段提交为边界，恢复阶段一代码和文档即可；未完成请求只存在于进程内存，回滚或进程退出后不得自动重放。回滚前必须停止控制层和 Executor，确认无活动子进程和后台线程。
