# AgentDesk 执行路线图

## 执行记录

实际开发进度、阶段状态、阻塞问题和变更历史见：[开发进度记录](../progress/progress.md)。

## 目标

交付一个由控制层和 Windows Executor 组成的远程桌面 AI 执行系统：控制层负责任务上下文、工具选择、权限策略、确认、调度和审计；Executor 只在已登录的 Windows 交互会话中执行经过认证和授权的动作。RustDesk 提供统一的远程画面、人工接管和业务消息传输会话。

## 交付原则

- 先稳定跨组件契约，再并行实现控制层和 Executor。
- 所有入口统一进入核心策略层，适配器不得绕过认证、授权、确认和审计。
- 先交付可观测、可取消、可审计的最小闭环，再增加高风险桌面能力。
- 高风险动作默认暂停并等待人工确认；人工接管时冻结新的副作用动作。

## 阶段路线

> 阶段编号表示交付顺序。后续阶段不得绕过前置阶段的退出条件。

### 第零阶段：技术基线

**目标**：建立能够持续开发和验证的工程基础。

**工作项**：

- 确定控制层与 Executor 的技术栈、目录结构和进程边界。
- 建立依赖管理、配置管理、日志规范、测试框架和持续集成。
- 明确本地开发环境、Windows 交互会话要求和最小启动方式。
- 编写第一条可复现演示流程和故障排查文档。

**交付物**：控制层和 Executor 项目骨架、构建脚本、基础测试、配置样例、启动文档和 CI 检查。

**验收标准**：新环境可以构建并启动两个组件；基础测试可自动运行；演示流程可被其他开发人员复现。

### 第一阶段：协议冻结

**目标**：冻结工具契约、消息格式和安全边界。

**工作项**：

- 定义工具目录、版本、输入模式、执行器、风险等级和超时上限。
- 定义请求、结果、错误、进度、取消和能力发现消息。
- 明确请求编号幂等、重放保护、签名、会话绑定和认证失败处理。
- 定义权限模型：工具、资源、动作、允许根目录、进程范围和 PowerShell 白名单。
- 定义确认令牌的绑定字段、有效期、一次性使用和审计字段。

**交付物**：协议规范、JSON Schema、错误类型表、状态机、风险分级表、安全决策记录。

**验收标准**：控制层和 Executor 可依据同一套契约完成校验；重复请求、过期请求、未授权请求和缺失确认令牌均有确定结果。

### 第二阶段：最小运行闭环

**目标**：完成单 Executor、单会话、单工具的端到端执行。

**工作项**：

- 实现会话、Executor 注册和能力发现。
- 实现统一请求流水线：认证、工具查找、参数校验、策略判断、调度、取消和结果归一化。
- 实现 Executor 工具注册表、请求校验、超时、取消和资源清理。

**交付物**：可运行的控制层、Windows Executor、本地安全通道、端到端测试工具。

**验收标准**：一次请求可从控制层发送到 Executor 并返回结构化结果；成功、参数错误、权限拒绝、超时、取消和 Executor 异常均可观测。

### 第三阶段：低风险工具

**目标**：用低副作用能力验证工具执行链路。

**工作项**：

- 实现屏幕截图、系统信息、窗口列表、前台窗口和进程查询。
- 为每个工具补齐契约、参数校验、超时、取消和结构化结果。
- 完成正常执行、失败、超时、取消和重复请求的集成测试。

**交付物**：低风险工具包、工具发现结果、集成测试和可复现演示。

**验收标准**：可完成“发现 Executor -> 查询窗口 -> 请求截图 -> 返回结构化结果”的完整流程。

### 第四阶段：安全策略与审计

**目标**：在开放写操作前建立可验证的安全边界。

**工作项**：

- 实现双向认证、请求签名和防重放。
- 实现工具、资源和动作级授权，以及策略拒绝。
- 实现审计记录、参数摘要和敏感数据脱敏。
- 验证路径、进程范围、身份伪造和重复请求等越权场景。

**交付物**：认证授权模块、策略配置、审计查询样例和安全测试。

**验收标准**：认证失败、权限拒绝和策略拒绝默认不可重试；所有调用可追溯到身份、请求编号和最终状态。

### 第五阶段：人工确认闭环

**目标**：让高风险请求可以安全地等待确认、继续或取消。

**工作项**：

- 实现 `awaiting_confirmation` 状态。
- 实现绑定请求编号、工具、参数摘要和有效期的一次性确认令牌。
- 验证令牌过期、重复使用、跨请求复用和参数变化场景。

**交付物**：确认流程、确认令牌模块和相关自动化测试。

**验收标准**：高风险动作确认前不会执行；确认、拒绝、过期和取消均生成审计记录。

### 第六阶段：MCP 控制入口

**目标**：让 Codex CLI 或兼容客户端通过 MCP 调用统一工具目录。

**工作项**：

- 实现 MCP 入口适配器和身份传递。
- 将 MCP 调用转换为统一请求，保留请求编号和调用上下文。
- 暴露工具目录、能力状态、进度和结构化错误。
- 确保 MCP 入口不能直接调用 Executor 或绕过核心策略。

**交付物**：MCP 服务器、客户端调用示例、协议兼容性测试。

**验收标准**：MCP 调用与内部调用使用完全一致的权限、确认、超时、取消和审计行为。

### 第七阶段：RustDesk 统一会话接入

**目标**：把工具消息、远程画面和人工接管放入同一会话体验。

**工作项**：

- 实现 RustDesk 会话适配器和会话绑定。
- 通过业务消息传输请求、进度、结果和取消消息。
- 保持中继只转发加密数据，不解析 AgentDesk 业务内容。
- 实现人工接管状态机：暂停新请求、取消可取消任务、重新获取画面和窗口状态后恢复。

**交付物**：统一会话适配器、人工接管流程、断连和恢复测试。

**验收标准**：用户可在远程画面与 AI 控制之间切换；交接期间不会基于过期状态继续执行副作用动作。

### 第八阶段：受控写操作

**目标**：以明确边界开放文件和剪贴板能力。

**工作项**：

- 实现允许根目录限制和路径规范化校验。
- 实现文件读写、剪贴板读写、敏感内容脱敏和失败清理。
- 明确无法回滚的写操作及其确认要求。

**交付物**：受控文件与剪贴板工具、权限配置和边界测试。

**验收标准**：目录穿越、越权路径和敏感数据写入日志均被拒绝或脱敏。

### 第九阶段：高风险执行能力

**目标**：谨慎开放输入、进程和 PowerShell 能力。

**工作项**：

- 使用命令白名单、资源限制和进程集合限制。
- 实现鼠标键盘操作、窗口操作和关键进程保护。
- 对管理员 PowerShell、删除、发送、支付、权限修改和外部写入强制确认。
- 完成副作用、取消、资源释放和 Executor 异常退出测试。

**交付物**：高风险工具包、强制确认策略和副作用测试报告。

**验收标准**：任意文件访问、任意进程终止和无限制 PowerShell 不作为默认能力提供。

### 第十阶段：扩展与试运行

**目标**：逐步覆盖初始范围中的执行能力。

**建议顺序**：屏幕截图 -> 鼠标键盘 -> 窗口管理 -> 剪贴板 -> 文件操作 -> 进程管理 -> UI 自动化 -> 受限 PowerShell。

**工作项**：

- 每项能力注册独立工具契约、风险等级、权限和超时上限。
- 对路径、进程标识、窗口目标和脚本参数执行严格校验。
- 对删除、发送、支付、权限修改、结束关键进程和外部写入统一要求确认。
- 为长任务实现进度、取消和临时资源释放。

**交付物**：分能力工具包、权限策略配置、桌面操作回归测试。

**验收标准**：每个工具都有成功、失败、超时、取消、拒绝和确认路径；越权路径无法通过参数变形绕过。

### 第十一阶段：生产化与扩展入口

**目标**：支持多入口、多 Executor 和生产环境运维。

**工作项**：

- 增加 CLI、HTTP、WebSocket 和 SDK 入口适配器，复用统一核心。
- 实现工具命名空间、契约版本升级和冲突拒绝。
- 增加断线重连、Executor 忙、临时连接错误和策略允许范围内的重试。
- 禁止副作用请求在 Executor 异常退出后自动重放。
- 增加指标、告警、审计查询、配置管理和发布文档。

**交付物**：扩展适配器、版本兼容策略、运维手册、安全测试报告和发布清单。

**验收标准**：新增入口不改变核心策略行为；关键故障可定位；审计可追溯到调用身份、请求编号和最终状态。

## 依赖关系与优先级

1. 协议、安全模型和错误语义是所有实现的前置条件。
2. 最小控制层与 Executor 闭环完成后，才能接入 MCP；MCP 验收后才能接入 RustDesk 会话。
3. RustDesk 人工接管最小闭环是受控写操作和高风险桌面能力上线的硬前置。
4. 低风险只读能力先于受控写操作、输入、进程和 PowerShell 能力。
5. 扩展入口和生产化治理应建立在核心行为稳定、可审计之后。

## 里程碑

- **M0：契约冻结**：协议、安全、风险和确认模型通过评审。
- **M1：最小闭环**：截图或系统信息请求端到端成功，失败与取消可验证。
- **M2：MCP 可用**：兼容客户端可发现并调用工具。
- **M3：统一会话**：RustDesk 画面、工具消息和人工接管闭环可用。
- **M4：桌面能力初版**：完成截图、输入、窗口、文件和 UI 自动化的分级发布。
- **M5：生产准备**：扩展入口、故障恢复、审计查询和发布检查完成，对应第十一阶段。

## 首批实施任务

1. 建立协议包和 JSON Schema。
2. 建立控制层与 Executor 的最小工程骨架。
3. 实现认证、请求编号、防重放和结构化错误。
4. 实现工具注册表、策略校验、调度、超时和取消。
5. 接入一个低风险只读工具并完成端到端测试。
6. 实现审计记录和敏感数据脱敏。
7. 在最小闭环稳定后接入 MCP。

## 每阶段退出条件

- 有可运行代码，而不是只增加设计文档。
- 有自动化测试，覆盖正常流程、权限拒绝、超时、取消和重复请求。
- 有针对当前能力的安全边界验证。
- 有可复现的演示流程和启动文档。
- 阶段验收通过后，才进入下一层能力，避免协议语义分叉。

## 持续验收门槛

- 每个工具都有契约、权限、风险、超时、取消和审计定义。
- 每次变更都验证认证、授权、确认、重放保护和人工接管边界。
- 高风险动作没有默认自动执行路径。
- Executor 不包含模型、任务规划或自主工具编排逻辑。
- 适配器只做协议转换和连接管理，核心策略行为保持一致。
