# 安全设计

状态：设计草案，未通过真实环境验证。本页维护安全决策规则；消息字段、状态与错误定义以[消息协议](../contracts/protocol.md)为准。下述规则是实施门禁，不代表系统已具备这些能力。

## 信任边界与认证

调用客户端、控制层、执行器、传输层是不同信任边界。控制层校验入口身份，签发可信的调用身份传播信息；执行器独立验证控制层、消息签名和目标绑定。客户端自报身份、工具发现信息和 RustDesk 登录均不能代替业务授权。

规划复用 RustDesk 的加密传输、远程画面和人工接管能力；业务层双向身份认证、密钥引导及会话绑定需要单独设计和测试。本地最小通道也必须具备相同认证及授权约束。中继只能接触业务密文，不应获得明文；这一要求需以集成测试证明，尚未验证。

权限绑定到受信调用者、工具、资源、动作、目标执行器和交互会话。锁定、切换用户、重连或权限变化必须重新检查。任何未知权限默认拒绝，管理员权限不作为默认能力。认证算法、信任根、轮换/吊销及密钥存储待第一阶段冻结。

## 风险与授权矩阵

风险同时考虑副作用与数据敏感性，不能把“只读”视为免授权或低敏感。下表为草案最低控制要求，策略可提高风险，不能由调用者降低。

| 级别 | 示例 | 权限与确认要求 |
|---|---|---|
| 低风险 `low` | 不含身份与内容的系统版本查询 | 明确读取权限；通常无需逐次确认，仍记录审计 |
| 中风险 `medium` | 截图、窗口信息、获准范围内的非敏感文件读取 | 校验目标、资源、内容策略；涉及敏感内容时升级或拒绝 |
| 高风险 `high` | 键鼠输入、文件/剪贴板写入、进程控制、受限脚本 | 逐请求确认、最小资源权限、执行前复核；有副作用时需接管门禁 |
| 不允许自动执行 | 无权限访问、无法识别的安全桌面、任意路径/进程/脚本、凭据直接进入日志 | 拒绝；可转人工完成独立操作，确认不得覆盖权限拒绝 |

文件限定允许根目录并防目录穿越、链接/重解析点逃逸和校验后替换；进程限定身份范围并核对创建时间以避免进程编号复用；脚本使用固定命令及参数约束，不能仅以字符串前缀代替解析。具体资源模型和边界实验由模块设计补齐后验收。

## 人工确认

删除、发送、支付、权限修改、关键进程控制及外部系统写入必须明确确认；输入操作按当前目标和可能副作用判定，不能仅根据鼠标或键盘工具名称降低风险。确认展示执行器、会话、工具、参数脱敏摘要、风险和失效时间，界面全部中文。

执行器维护待确认挑战；控制层验证审批者拥有该目标和风险范围的审批权限，再签发一次性令牌并提交。令牌绑定会话、执行器、请求、工具及版本、参数摘要、原调用者、审批者、挑战编号、唯一令牌编号和有效期。签发方必须受执行器信任，调用者不能自行伪造审批主体。

令牌消费和状态迁移原子化，重复提交不能重复调度；参数、身份或目标变化必须创建新请求。批准后仍需重新授权。拒绝、取消、过期和接管撤销都生成审计记录。具体令牌序列化、签名和审批权限配置待冻结。

## 特殊 Windows 会话

锁定、切换用户、安全桌面或管理员提示出现时暂停自动输入，不能把人工确认当成突破系统隔离的手段。需要用户在本地或远程交互会话手工处理；恢复前重新认证目标会话、获取画面与窗口状态，撤销旧确认。凭据、支付页面、敏感文件与剪贴板内容按最小读取原则处理；无明确策略时拒绝采集。

## 人工接管

控制层停止发送新的自动化执行请求，执行器同时冻结尚未执行的请求，撤销未消费确认，按工具能力停止在途任务；状态查询、取消和必要审计回传仍允许。无法取消的动作标记为未停止并向用户展示，不承诺副作用已回滚。

自动键鼠与人工输入互斥，自动文件、进程、脚本等副作用也受冻结约束。接管期间不启动新的读工具；恢复时在策略批准的刷新步骤读取最新画面与窗口状态，核对会话，再接受新请求。旧队列不得直接续跑。互斥及冻结传播的实现方案和故障测试是 RustDesk 阶段退出条件。

## 审计、数据与故障

审计关联身份、签名者、请求/消息编号、会话/执行器、工具版本、参数摘要、策略/确认决定、状态时间、错误和清理结果。控制层与执行器分别记录其负责的事件，通过请求编号关联，不能将一侧日志当成另一侧执行成功证据。

密码、令牌、原始剪贴板、文件正文和截图不进入普通日志。输出走受授权的结果通道，大小、留存、访问和删除策略待冻结；摘要亦可能泄露低熵秘密，敏感参数采用遮蔽或受控摘要。审计不可用时拒绝启动新的副作用动作，不能为写日志阻塞紧急停止；恢复后补记停止事实并标识缺口。存储与补记机制未验证。

认证、权限与策略拒绝不自动重试。协议幂等处理仅返回原状态，不重复执行；断连、超时或崩溃后先查询并核实副作用，未知结果需人工处理。令牌消费、状态保存、调度与审计之间的崩溃一致性必须验证，不能承诺桌面动作与存储事务可以整体回滚。
